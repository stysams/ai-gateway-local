# 运维与故障排查

## 网络边界

网关默认监听 `127.0.0.1`。只有明确配置 `listen.host: 0.0.0.0` 才提供局域网数据面访问；`/api/v1/*` 管理接口始终只接受真实 TCP 回环来源，不信任 `X-Forwarded-For` 等转发头。暴露局域网数据面前，应先在防火墙和网络设备上限制来源。

## 密钥与配置

提供商密钥只写入操作系统密钥存储。配置、客户端文件、管理响应、日志和指标都不得包含真实密钥。修改 `config.yaml` 前先复制整个数据目录；原子写失败时保留旧配置，恢复时应停止网关、还原配置备份、确认 `readyz`，再启动服务。

## 资源限制

`limits.global`、`limits.per_client` 和 `limits.per_provider` 的范围是 `0..1024`，零值关闭对应并发限制。`stream_idle_seconds` 只限制连续无数据间隔，不限制持续输出的总时长。`request_body_bytes`、`request_header_bytes` 和 `client_rate_per_minute` 分别控制请求体、请求头和单客户端固定一分钟窗口。超限返回协议原生 `413`、`431` 或 `429`，拒绝请求不会接触上游。

## 日志、保留和恢复

日志默认保留，正文日志可能包含提示词、源码、工具参数和工具结果。启用 `logging.retention_days` 或 `logging.quota_bytes` 后，网关在启动时清理已完成请求日志；活动请求和中断日志永不因保留策略删除。清理前应先关闭正文日志并备份 `logs/`，发生误删或磁盘故障时只能从外部备份恢复。

## 指标与熔断

`GET /api/v1/metrics` 返回请求计数、成功/失败/取消、状态分类、P50/P95 总延迟和首字节延迟、上游错误、活跃请求和活动日志会话，不返回正文或密钥。连续三次上游连接失败、超时或 `5xx` 后，网关按 provider 短暂熔断并返回 `503 provider_circuit_open`。429、客户端错误和可能产生副作用的请求不自动重试。

排查顺序建议为：先检查 `/healthz` 和 `/readyz`，再检查 `/api/v1/metrics`、`/api/v1/doctor`、提供商探测和最近请求日志。不要把网关自身的 `429` 与上游返回的 `429` 混为一谈。

## 升级与回滚

升级前停止桌面和网关，备份 `config.yaml`、`secrets/`、`logs/` 和客户端配置。替换程序后先运行 `doctor`、`readyz` 和指标接口检查，再逐个恢复客户端指向。回滚时恢复同一份配置、密钥和客户端备份，不要把新版本配置直接覆盖旧版本而跳过校验。

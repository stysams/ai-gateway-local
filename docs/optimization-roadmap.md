## 1. 历史优化前基线

以下内容是优化工作开始前的历史基线，不代表当前 `0.1.0-rc1` 实现：

- `go test ./...` 通过。
- `go vet ./...` 通过。
- `npm --prefix desktop run test` 通过：6 个测试文件、36 个测试。
- `npm --prefix desktop run lint` 通过。
- `npm --prefix desktop run build` 通过。
- `npm --prefix desktop run test:e2e` 通过：桌面明色和移动暗色共 16 个测试。
- 优化前基线已生成：[`baseline-2026-08-22.md`](baseline-2026-08-22.md)，六百个日志文件、并发 1/8/32、每档 200 次请求。

优化前实现中与历史任务直接相关的事实：

| 领域 | 优化前行为 | 主要位置 | 历史风险 |
|---|---|---|---|
| 请求体 | 数据面最多允许 128 MiB，并先完整读入内存 | `internal/server/dataplane.go` | 大请求、并发请求和正文日志会放大内存分配 |
| 配置读取 | `Snapshot()` 返回深复制 | `internal/config/manager.go` | 每个数据面请求都可能产生复制和分配 |
| 日志写入 | 每个 JSONL 事件重新打开和关闭文件 | `internal/logstore/store.go` | 高频流式请求的系统调用和延迟较高 |
| 日志查询 | 遍历日志文件、解析摘要、排序后返回 | `internal/logstore/store.go` | 日志量增长后查询成本近似随文件数增长 |
| 管理边界 | 管理面和数据面共用监听器；`0.0.0.0` 会同时暴露二者 | `internal/server/handlers.go`、`server.go` | 远程监听时配置、日志和关闭接口缺少独立防护 |
| 桌面刷新 | 一次操作完成后并行刷新多类资源 | `desktop/src/App.tsx` | 小范围变更会触发全量刷新，组件文件也较大 |
| 可观测性 | 主要依赖请求 JSONL 和管理接口 | `internal/server/trace.go`、`logstore` | 缺少延迟、并发、上游失败率等运行时指标 |

## 2. 归档说明

本路线图记录的 G0 至 G5 任务均已完成、取消或转入 `docs/progress.md` 的历史验收遗留。现有 `0.1.0-rc1` 是唯一版本基准；不会因为路线图中的任务编号、依赖关系或完成定义继续启动新工作。

`G0-02`、各优化任务和 `REL-01` 的状态保留，用于说明当前实现的来源和验证证据，不代表仍有待执行的发布计划。

历史基线 `2f7c9344027b394bfec64eb7254c832ba930fde4` 仍用于性能比较。现有版本包的元数据以 [progress.md](progress.md) 和 [release-notes.md](releases/release-notes.md) 为准。

本路线图不再要求启动优化任务前记录新的内容。历史任务曾记录：

1. 第一阶段发布版本、完整提交哈希和平台。
2. `go test ./...`、`go vet ./...`、桌面测试、Lint、构建和端到端测试结果。
3. 当前内存、请求延迟、日志查询耗时和磁盘占用基线。
4. 任务要解决的用户可见问题，以及明确不改变的协议行为。

### 2.2 完成定义

历史任务只有同时满足以下条件才可以标记为“已完成”：

- 有实现或明确的测量结果，且变更范围与任务编号一致。
- 有针对风险的单元、集成、竞态、基准或端到端验证。
- 外部行为发生变化时，规格、README、安装说明或运维文档已经同步。
- 敏感信息没有进入配置文件、客户端配置、管理响应、日志或测试夹具。
- 影响发布二进制时，按照 `CLAUDE.md` 和 `progress.md` 重新打包并记录版本。
- 任务证据已写入当天 `memory/YYYY-MM-DD.md`。

状态含义：

- `待启动`：已排入路线图，尚未执行。
- `进行中`：已建立分支或工作区，正在实现或测量。
- `阻塞`：有明确外部依赖，已记录证据，不能靠继续修改代码解除。
- `已完成`：通过本任务的验收标准。
- `取消`：经明确决策不再执行，并保留原因。

## 4. 历史执行顺序

```text
G0-01 → G0-02
          ├─→ SEC-01
          ├─→ RES-01 → RES-02 → SEC-02
          ├─→ PERF-01 → PERF-02 → PERF-03
          ├─→ LOG-01 → LOG-02 → LOG-03
          │              └─→ OBS-01 → OBS-02
          ├─→ UI-01 → UI-02 → UI-03
          └─→ TEST-01 → TEST-02

任一发布级变更 → REL-01
```

上述顺序仅说明历史实现依赖，当前不再启动新的主体优化任务，也不从中派生新的发布计划。版本状态和历史验收遗留统一记录在 [progress.md](progress.md)。

## 5. 当前版本边界（归档）

- 不根据本路线图启动新的 G1 至 G5 发布级实现任务。第一期遗留问题保留在 `docs/progress.md` 第 13 节，不自动转为当前版本的新任务。
- 不升级 Wails、Go 工具链或 React/Vite 依赖，除非建立独立升级任务并完成兼容性证据。
- 不改变现有三种协议、路由解析、客户端目录和最小改写合同来换取测试通过。
- 不把真实 API 密钥写入配置、客户端文件、管理响应、日志、基准输出或测试夹具。
- 不对有副作用的上游请求默认自动重试。
- 不把桌面进程改造成 `/v1/*` 数据面服务。
- 不将本路线图中的历史任务误标为当前版本的新增规划或新的第一期完成条件。

## 6. 历史任务记录格式

历史任务曾在本表补充以下信息；当前不再按此模板启动任务：

```text
任务：<编号> <名称>
状态：进行中 / 阻塞 / 已完成
范围：<文件、接口或基准范围>
不变项：<明确不能变化的协议或用户行为>
证据：<测试、基准、日志或真实验收记录>

发布：<是否需要重新打包；版本和提交哈希>
```

任务完成后必须同步：

1. 本文对应行的状态和说明。
2. 受影响的规格、README、安装文档或运维文档。
3. 相关测试和基准结果。
4. 当天 `memory/YYYY-MM-DD.md` 任务日记。
